# ブログ戦略

## 目的

開発過程をそのまま技術ブログ・ポートフォリオの素材にする。
「動かす」だけでなく「なぜそう設計したか」を残すことを重視する。

## 記事化しやすくする工夫（設計意図）

- 1 機能 = 1 PR = 1 記事 を基本単位にする。
- 各実装で「設計判断」と「ハマりどころ」を簡潔にメモする。
- Issue / PR に「何を・なぜ」を残し、それを記事に転用する。

## 記事の基本構成テンプレート

```
1. 何を作るか / 課題
2. 設計の選択肢と判断理由
3. OpenAPI 定義（抜粋）
4. 実装（Rails / Next.js の要点）
5. テスト（Request Spec の例）
6. ハマったこと・学び
7. まとめ
```

## 執筆予定テーマ

- API 駆動開発とは
- OpenAPI の設計方法
- Next.js × Rails のフルスタック構成
- public_id によるリソース ID 設計
- Pundit による認可設計
- Request Spec 実践
- N+1 問題と対策
- 勤怠システムの DB 設計
- AI（Claude Code）を活用した開発フロー

## 運用ルール

- 各機能の実装後、記事用メモ（設計意図・判断・つまずき）を残す。
- コードと記事で用語を揃える（public_id、認可、Request Spec など）。
- 初学者にも伝わる言葉で説明できる粒度を保つ。
