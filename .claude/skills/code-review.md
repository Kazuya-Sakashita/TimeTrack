# Skill: コードレビュー

実装後・PR 前のセルフレビューの観点。

> レビュー（評価）を行うため、`framework-based-planning.md` に従い、
> 使用フレームワーク・採用理由・評価結果・次のアクションを明記すること。

## いつ使うか

- 実装が一区切りついたとき
- PR を出す前

## レビュー観点

### 仕様
- [ ] OpenAPI と実装が一致しているか
- [ ] 仕様にないフィールド / 挙動を追加していないか

### セキュリティ
- [ ] 内部 id が外部に漏れていないか（public_id を使っているか）
- [ ] 認証（401）・認可（403）が要件どおりか
- [ ] 認可ロジックが Pundit Policy に集約されているか
- [ ] 秘密情報をハードコードしていないか

### 設計
- [ ] Controller が薄いか（ロジックは Model/Service）
- [ ] N+1 を避けているか
- [ ] フロントは型安全か（any を避けているか）

### テスト
- [ ] Request Spec があるか（正常 + 異常 + 認可）
- [ ] 完了の定義を満たすか

### 粒度・記事化
- [ ] PR が 1 目的に収まっているか（巨大でないか）
- [ ] 設計意図 / つまずきメモを残したか（ブログ素材）

## 進め方

1. 上の観点で diff を確認する。
2. 問題があれば修正する。
3. 残課題があれば Issue 化する。
4. 変更ファイル一覧と次の一手をまとめる。
