# Skill: ブログ執筆支援

実装内容を技術ブログ記事にまとめるときの進め方。

> 記事構成（評価・設計）には `framework-based-planning.md` に従い、
> PREP / 課題→解決→学び / Before After などのフレームワークを使う。

## いつ使うか

- 1 つの機能 / PR が完成したとき
- 設計判断を記事として残したいとき

## 判断基準

- 1 記事 = 1 機能 / 1 テーマに収まっているか。
- 「なぜそう設計したか」が書けているか（手順だけになっていないか）。
- 初学者にも伝わる言葉か。

## 記事構成テンプレート

```
1. 何を作るか / 課題
2. 設計の選択肢と判断理由
3. OpenAPI 定義（抜粋）
4. 実装の要点（Rails / Next.js）
5. テスト（Request Spec の例）
6. ハマったこと・学び
7. まとめ
```

## 進め方

1. 対象機能の PR / Issue / 設計メモを集める。
2. テンプレートに沿って骨子を作る。
3. コードは要点のみ抜粋し、長くなりすぎない。
4. 用語をプロジェクトと揃える（public_id / 認可 / Request Spec）。

## チェックリスト

- [ ] 1 テーマに絞れている
- [ ] 設計理由が書かれている
- [ ] コード抜粋が適量
- [ ] 用語が一貫している
- [ ] 初学者にも説明できる粒度
