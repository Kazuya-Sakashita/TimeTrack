# Skill: テスト (RSpec / Request Spec)

API のテストを書くときの進め方。主軸は Request Spec。

## 判断基準

- API の契約（入出力・ステータス・認可）を検証できているか。
- 異常系・権限系まで書けているか。

## 進め方

1. 対象 API の OpenAPI 定義を確認する。
2. Request Spec で正常系を書く（期待ステータス・レスポンス）。
3. 異常系を書く（未認証 401 / 権限なし 403 / バリデーション 422 / 不在 404）。
4. ロール別（従業員 / 管理者）の可否を検証する。
5. 必要に応じて Model Spec / Policy Spec を補う。
6. テストデータは factory で用意する。

## チェックリスト

- [ ] 正常系のステータス・レスポンスを検証
- [ ] 未認証 → 401 を検証
- [ ] 権限なし → 403 を検証
- [ ] バリデーション失敗 → 422 を検証
- [ ] レスポンスが OpenAPI と一致（public_id が返る）
- [ ] ロールごとの可否（Policy Spec）

## 完了の定義

- OpenAPI 定義あり + 実装あり + Request Spec 通過（正常 + 異常 + 認可）。

## やってはいけない

- 正常系だけで完了とする
- 認可の検証を省く
